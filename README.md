# 67launcher-safe

Безопасный форк [67Launcher](https://github.com/KotiPlayYT/67launcher).

Функционал оригинала сохранён полностью - тимвиевер, чат, комнаты, личные
переписки, моды, скины, ресурспаки, установка клиентов. Ничего не выпилено.
Добавлено только то, чего не хватало: **явные согласия на опасные действия**
и **один тумблер, чтобы выключить всё опасное разом**.

Конфиги (в частности адрес релея) намеренно тянутся с апстрима
`KotiPlayYT/67launcher` - так форк получает свежие настройки официального
лаунчера.

## Что изменено по сравнению с оригиналом

| Что | Как было | Как стало |
|---|---|---|
| Фаервол | `add_firewall_rule()` молча открывал TCP 25565 и 25560-25570 навсегда | Правило добавляется только после явного "Да"; есть кнопка удаления в Настройки → Безопасность |
| Safe mode | не было | Один тумблер отключает удалённый ввод, трансляцию экрана, запуск файлов и автозапуск раздаваемых файлов. По умолчанию **выключен** |
| Запрос трансляции экрана | один диалог "Да/Нет" | Два подтверждения: объяснение, что это полный доступ к ПК, затем галка о полном осознании |
| Плашка трансляции | создавалась, но не присваивалась - баг, `stop_screen_share` нечего было закрывать | Плашка реально появляется поверх всех окон и останавливает трансляцию одним кликом |
| Удалённый ввод | молча выполнялся | Каждый клик и каждое нажатие клавиши пишется в лог чата |
| Запуск скачанного файла | один "Да/Нет" | Для `.exe/.bat/.ps1` и т.п. нужно вписать слово `ЗАПУСТИТЬ` |
| Скачивание файла | без хеша | Показывается SHA-256, чтобы сверить с отправителем |
| Релей | менялся молча | Смена адреса пишется в лог, в настройках чата видно, куда уходят сообщения |
| Смена релея при работе | не отслеживалась | Раз в 60 секунд проверяется `relay.active.txt`, при смене адреса лаунчер спрашивает и переключается только по "Да" |
| Ссылка в чате | только полный URL | Показывается домен |
| Заявка в друзья | добавляла в "Чаты" молча | Спрашивает подтверждение |

## Проверка смены релея

Адрес релея лежит в `relay.active.txt` в репозитории `KotiPlayYT/67launcher`
и может смениться в любой момент. Значит сообщения могут уйти на чужой сервер,
и юзер об этом не узнает.

Лаунчер раз в 60 секунд тихо спрашивает у GitHub текущий адрес и сравнивает
его с тем, на котором уже работает:

- адрес не менялся - ничего не происходит, сетевых запросов больше нет
- адрес сменился - появляется диалог со старым и новым адресом
- ответ "Нет" - лаунчер остаётся на старом адресе и больше не спрашивает
  про этот адрес (вернётся к вопросу, только если придёт другой адрес)
- ответ "Да" - адрес применяется, открытые чаты переподключаются
- диалог не показался или его закрыли крестиком - адрес не применяется

Переключение выполняется **только по явному "Да"**. Тихих применений нет.

Отключается тумблером "Проверять смену релея" в настройках чата
(по умолчанию включён). Выключенный тумблер полностью прекращает запросы
к GitHub. Чаты, у которых юзер вписал свой адрес релея руками, не
переключаются - смена глобального адреса их не касается.

## Как обновляться из апстрима

Форк **не обновляется автоматически**. Перед каждым rebase обязательно
прогоняется аудит: `upstream` - чужий репозиторий, и доверять его содержимому
без проверки нельзя.

```bash
# один раз настроить remote
git remote add upstream https://github.com/KotiPlayYT/67launcher
git fetch upstream
```

Дальше перед каждым обновлением:

```bash
./scripts/check_upstream.sh          # или: python scripts/check_upstream.py
```

Скрипт **ничего не применяет** - только читает историю и печатает отчёт
по трём вопросам:

1. **Менялся ли код** - `main.py`, `requirements.txt`, `setup.py`, `pyproject.toml`
   (если менялся `main.py`, печатаются добавленные строки с опасными вызовами:
   `subprocess`, `pyautogui`, `eval`, `urllib`, чтение `accounts.json`, голые URL)
2. **Появились ли исполняемые файлы** - `*.exe`, `*.dll`, `*.jar`, `*.zip`, `*.ps1` …
   и не появилось ли в `resources/` чего-то, что не картинка и не звук
3. **Менялся ли адрес релея** - `relay.active.txt`, с показом старого и нового URL

Коды возврата: `0` - обновляться не нужно, `1` - нужен разбор,
`2` - ошибка окружения, `3` - нет сети.

### Если аудит чист и релеяет смысл

```bash
git fetch upstream
git rebase upstream/main
# конфликты решаем В ПОЛЬЗУ НАШИХ ПРАВОК БЕЗОПАСНОСТИ,
# docstrings не выпиливаем - в этом коде они несут смысл
python -m py_compile main.py
python scripts/check_upstream.py --quiet   # должно быть 0
git push origin main
```

### Что считать "грязным" апстримом

- в `main.py` добавились вызовы `subprocess`, `eval`, `exec`, `__import__`,
  `urllib`, `pyautogui`, `ctypes` - особенно с новым URL
- появились `.exe`, `.dll`, `.jar`, `.zip`, `.ps1`, `.bat` в репозитории
- в `resources/` появилось что-то, что не `.gif/.png/.mp3`
- `relay.active.txt` указывает на незнакомый домен
- новый `.py` файл, которого не было - прочитать целиком

Молчаливое "автор просто перезалил картинки" - тоже повод посмотреть глазами:
для этого и существует `check_upstream.sh`.

## Известный баг апстрима

`LauncherApp.launch_game()` вызывал `self.show_first_launch_server_dialog`,
но такого метода в `KotiPlayYT/67launcher` (495c0f7) нет - на первом запуске
игры это давало `AttributeError`. Вызов отключён с пометкой `TODO(upstream)`:
своего диалога форк не придумывает, и как только автор добавит метод,
строку достаточно раскомментировать.
